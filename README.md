# Marketplace Research — анализ выдачи маркетплейсов

Локальный инструмент для исследования ниши перед запуском товарной линейки.
Первый кейс — полотенца (эко-полотенца, наборы, банные).

Что делает:

1. **Собирает** карточки товаров по списку поисковых запросов с Wildberries
   (публичный поисковый endpoint, без платных API и без авторизации).
2. **Считает аналитику**: цены, рейтинги, отзывы, бренды, частые слова в названиях,
   форматы товара (одиночное / набор / подарочный набор / банное / бамбук / хлопок ...).
3. **Собирает отчёты** в Markdown: сводка по рынку и практические выводы под запуск.

Поисковые запросы лежат в `data/queries.csv`, все настройки — в `config.yaml`.
В коде ничего менять не нужно.

---

## Установка

Нужен Python 3.10 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Запуск

```bash
python scripts/collect_wb.py        # 1. сбор карточек с Wildberries
python scripts/analyze_products.py  # 2. аналитика
python scripts/generate_report.py   # 3. отчёты в Markdown
```

Сбор 20 запросов занимает примерно 1–2 минуты (между запросами стоит пауза,
чтобы не получить бан по IP).

Полезные флаги:

```bash
python scripts/collect_wb.py --sample     # не ходить в сеть, работать на мок-данных
python scripts/collect_wb.py --top-n 30   # брать по 30 карточек вместо 20
```

## Где смотреть результаты

| Файл | Что внутри |
|---|---|
| `data/products.csv` | Все собранные карточки одной таблицей (открывается в Excel/Numbers) |
| `data/raw_wb_products.json` | Сырые ответы Wildberries — на случай, если понадобится больше полей |
| `reports/summary.md` | Сводка: сколько собрали, топ брендов, ценовой коридор, самые «отзывные» запросы |
| `reports/launch_recommendations.md` | Выводы под запуск: коммерческие запросы, цены, форматы, гипотезы по SKU |
| `reports/query_analysis.csv` | Цифры по каждому поисковому запросу |
| `reports/format_analysis.csv` | Цифры по форматам товара (набор, банное, бамбук и т. д.) |
| `reports/price_buckets.csv` | Сколько карточек в каждой ценовой корзине |

Начинать чтение стоит с `reports/launch_recommendations.md`.

## Как поменять запросы

Откройте `data/queries.csv` и добавьте строки — по одному запросу в строке,
первая строка `query` (заголовок) остаётся на месте. Затем прогоните три команды заново.

## Настройки (`config.yaml`)

- `marketplaces.wildberries.top_n` — сколько карточек брать по запросу;
- `marketplaces.wildberries.dest` — регион доставки (влияет на цены);
- `marketplaces.wildberries.request_delay_sec` — пауза между запросами;
- `analysis.min_reviews_for_strong_card` — с какого числа отзывов карточка считается «сильной»;
- `analysis.price_buckets` — границы ценовых корзин;
- `analysis.formats` — по каким словам в названии определяется формат товара.

## Если Wildberries не отвечает

WB иногда меняет версии поискового endpoint, а часть сетей и хостингов его блокирует.
Скрипт не падает: он пробует три версии API, делает ретраи, а если данных нет совсем —
**переключается на fallback с мок-данными** `data/sample_products.csv`
(генерируются автоматически при первом запуске). Анализ и отчёты на них работают
полностью, но **цифры в этом режиме выдуманные** — их нельзя использовать для решений.

Как понять, что сработал fallback: в консоли будет строка
`Wildberries не ответил ни по одному запросу — включаю fallback на мок-данные`,
а `data/raw_wb_products.json` (если живого сбора ещё не было) будет содержать пометку
вместо сырых ответов.

Что делать:

1. Проверьте, открывается ли `https://search.wb.ru` из вашей сети (VPN/прокси, корпоративный
   фаервол, хостинг за пределами РФ — частые причины блокировки).
2. Откройте wildberries.ru в браузере, в DevTools → Network найдите запрос `.../search?...`
   и сверьте версию (`v13`, `v14` и т. д.) и параметры.
3. Добавьте актуальный URL первым в список `SEARCH_ENDPOINTS` в `scripts/collect_wb.py`.

> В окружении, где проект собирался, `search.wb.ru` заблокирован сетевой политикой,
> поэтому пайплайн проверен на мок-данных. Живой сбор нужно прогнать на своей машине
> и, если endpoint сменился, поправить `SEARCH_ENDPOINTS`.

## Что можно добавить дальше

Архитектура специально плоская и рассчитана на расширение:

- **Ozon**: добавить `scripts/collect_ozon.py`, который пишет строки в том же формате
  (`common.PRODUCT_COLUMNS`) с `marketplace=ozon` и дописывает их в `data/products.csv`.
  Аналитика и отчёты читают эту таблицу как есть — правок в них не потребуется,
  останется только добавить группировку по `marketplace`, если нужно сравнение площадок.
- **Отзывы**: отдельный скрипт по `product_id` из `products.csv` + анализ частых жалоб.
- **Динамика**: сохранять `products.csv` с датой в имени и считать прирост отзывов —
  это косвенная оценка объёма продаж.
