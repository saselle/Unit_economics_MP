# Marketplace Research — анализ выдачи маркетплейсов

Локальный инструмент для исследования ниши перед запуском товарной линейки.
Первый кейс — полотенца (эко-полотенца, наборы, банные).

Что делает:

1. **Собирает** карточки товаров по списку поисковых запросов с Wildberries
   (публичный поисковый endpoint, без платных API и без авторизации).
2. **Считает аналитику**: цены, рейтинги, отзывы, бренды, частые слова в названиях,
   форматы товара (одиночное / набор / подарочный набор / банное / бамбук / хлопок ...).
3. **Собирает отчёты** в Markdown: сводка по рынку и практические выводы под запуск.

Поисковые запросы лежат в `data/queries.csv`, все настройки — в `config.yaml`.
В коде ничего менять не нужно.

## Установка

Нужен Python 3.10 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Запуск в один клик

**Windows:** откройте двойным щелчком файл **`Запустить анализ.bat`** в папке проекта.
Он сам поставит недостающие библиотеки и прогонит все шаги: сбор выдачи, сбор отзывов,
аналитику, отчёты в Markdown, Excel и Word. В конце покажет список собранных файлов.

**macOS / Linux** (и Windows, если удобнее из консоли):

```bash
python scripts/run_all.py                  # всё целиком
python scripts/run_all.py --skip-reviews   # без отзывов, быстрее
python scripts/run_all.py --skip-collect   # пересчитать отчёты на уже собранных данных
python scripts/run_all.py --top-n 30 --reviews-top 40   # глубже выдача и больше отзывов
```

Шаг, который не удался, не останавливает остальные: если WB не отдал отзывы,
отчёты по выдаче всё равно соберутся.

## Запуск по шагам

Те же действия по отдельности — когда нужно перезапустить только часть:

```bash
python scripts/collect_wb.py        # 1. сбор карточек с Wildberries
python scripts/analyze_products.py  # 2. аналитика
python scripts/generate_report.py   # 3. отчёты в Markdown
python scripts/export_excel.py      # 4. тот же отчёт в Excel
python scripts/export_docx.py       # 5. выводы в Word
python scripts/build_matrix.py      # 6. матрица SKU + заготовка юнит-экономики
python scripts/build_specs.py       # 7. ТЗ поставщику по каждой позиции матрицы
```

Отдельный блок — отзывы конкурентов (нужен уже собранный `data/products.csv`):

```bash
python scripts/collect_reviews.py   # отзывы по топ-15 карточкам выдачи
python scripts/analyze_reviews.py   # темы жалоб и похвал
python scripts/export_excel.py      # добавит листы с отзывами в тот же Excel
```

Сколько карточек обходить и какие темы искать — в `config.yaml`, секция `reviews`.
Отзывы на WB лежат не по артикулу, а по «корневой» карточке (общей для всех
цветов и размеров), поэтому скрипт сначала узнаёт её id, а потом качает отзывы.

Сбор 20 запросов занимает примерно 1–2 минуты (между запросами стоит пауза,
чтобы не получить бан по IP).

Полезные флаги:

```bash
python scripts/collect_wb.py --sample     # не ходить в сеть, работать на мок-данных
python scripts/collect_wb.py --top-n 100  # брать по 100 карточек вместо 20
```

## Где смотреть результаты

| Файл | Что внутри |
|---|---|
| `data/products.csv` | Все собранные карточки одной таблицей (открывается в Excel/Numbers) |
| `data/raw_wb_products.json` | Сырые ответы Wildberries — на случай, если понадобится больше полей |
| `reports/summary.md` | Сводка: сколько собрали, топ брендов, ценовой коридор, самые «отзывные» запросы |
| `reports/launch_recommendations.md` | Выводы под запуск: коммерческие запросы, цены, форматы, гипотезы по SKU |
| `reports/query_analysis.csv` | Цифры по каждому поисковому запросу |
| `reports/format_analysis.csv` | Цифры по форматам товара (набор, банное, бамбук и т. д.) |
| `reports/price_buckets.csv` | Сколько карточек в каждой ценовой корзине |
| `data/reviews.csv` | Отзывы по карточкам конкурентов: оценка, дата, текст, плюсы, минусы, цвет, размер |
| `reports/reviews_summary.md` | На что жалуются и за что хвалят — готовое ТЗ поставщику и текст для карточки |
| `reports/review_themes.csv` | Темы отзывов: частота, средний рейтинг, доля негатива, пример |
| `reports/review_by_product.csv` | Главные жалобы и плюсы по каждой карточке конкурента |
| `reports/marketplace_report.xlsx` | **Excel**: сводка, все карточки с фильтрами, срезы по запросам, форматам и ценам |
| `data/sku_matrix.csv` | Матрица SKU: размеры, цвета, плотность, состав, таргет по цене — правится вручную |
| `reports/Матрица_SKU.xlsx` | **Excel**: матрица с бенчмарком от выдачи, срез по цветам из отзывов и заготовка юнит-экономики |
| `reports/Отчёт_по_рынку.docx` | **Word**: выводы под запуск — файл, который не стыдно отправить клиенту |
| `reports/ТЗ_поставщику.docx` | **Word**: ТЗ по каждой позиции матрицы — требования, привязанные к жалобам из отзывов |
| `reports/ТЗ_по_позициям.md` | Тот же документ текстом — удобно копировать в переписку с фабрикой |

Цифры на листах Excel — формулы, считающие от листа «Карточки»: отфильтруете или
дополните данные — отчёт пересчитается сам. Использованы только функции,
понятные любой версии Excel (`COUNTIF`, `AVERAGEIFS`, `QUARTILE`), без новых
формул-массивов.

Начинать чтение стоит с `reports/launch_recommendations.md`.

Файлы, открытые в Word или Excel, Windows не даёт перезаписать. Скрипты это
переживают: результат сохраняется рядом, с пометкой «(новая версия)» в имени,
и в консоли появляется предупреждение. Закройте файл и запустите заново —
обновится оригинал.

## Как поменять запросы

Откройте `data/queries.csv` и добавьте строки — по одному запросу в строке,
первая строка `query` (заголовок) остаётся на месте. Затем прогоните три команды заново.

## Настройки (`config.yaml`)

- `marketplaces.wildberries.top_n` — сколько карточек брать по запросу. Это верх
  выдачи по сортировке «популярные» — то, что видит покупатель на первых экранах.
  До 100 укладывается в одну страницу, больше — скрипт листает выдачу дальше;
- `marketplaces.wildberries.dest` — регион доставки (влияет на цены);
- `marketplaces.wildberries.request_delay_sec` — пауза между запросами;
- `analysis.min_reviews_for_strong_card` — с какого числа отзывов карточка считается «сильной»;
- `analysis.price_buckets` — границы ценовых корзин;
- `analysis.formats` — по каким словам в названии определяется формат товара.

## Если Wildberries не отвечает

WB иногда меняет версии поискового endpoint, а часть сетей и хостингов его блокирует.
Скрипт не падает: он пробует три версии API, делает ретраи, а если данных нет совсем —
**переключается на fallback с мок-данными** `data/sample_products.csv`
(генерируются автоматически при первом запуске). Анализ и отчёты на них работают
полностью, но **цифры в этом режиме выдуманные** — их нельзя использовать для решений.

Как понять, что сработал fallback: в консоли будет строка
`Wildberries не ответил ни по одному запросу — включаю fallback на мок-данные`,
а `data/raw_wb_products.json` (если живого сбора ещё не было) будет содержать пометку
вместо сырых ответов.

Что делать:

1. Запустите диагностику — она сама переберёт версии адреса, параметры и заголовки:

   ```bash
   python scripts/check_wb.py
   ```

   Скрипт сначала проверяет сам сайт wildberries.ru: если и он отвечает 403,
   дело в IP (включён VPN или зарубежный адрес), а не в коде.

2. Если WB отвечает 403 на все варианты — почти наверняка он отсекает запрос по
   TLS-отпечатку Python. Помогает `curl_cffi` (входит в requirements.txt),
   она повторяет отпечаток настоящего Chrome:

   ```bash
   pip install curl_cffi
   ```

   Скрипты подхватывают её автоматически и печатают `Движок запросов: curl_cffi`.

3. Проверьте, открывается ли `https://search.wb.ru` из вашей сети (VPN/прокси, корпоративный
   фаервол, хостинг за пределами РФ — частые причины блокировки).
4. Откройте wildberries.ru в браузере, в DevTools → Network найдите запрос `.../search?...`
   и сверьте версию (`v13`, `v18` и т. д.) и параметры.
5. Добавьте актуальный URL первым в список `SEARCH_ENDPOINTS` в `scripts/collect_wb.py`.

> В окружении, где проект собирался, `search.wb.ru` заблокирован сетевой политикой,
> поэтому пайплайн проверен на мок-данных. Живой сбор нужно прогнать на своей машине
> и, если endpoint сменился, поправить `SEARCH_ENDPOINTS`.

## Что можно добавить дальше

Архитектура специально плоская и рассчитана на расширение:

- **Ozon**: добавить `scripts/collect_ozon.py`, который пишет строки в том же формате
  (`common.PRODUCT_COLUMNS`) с `marketplace=ozon` и дописывает их в `data/products.csv`.
  Аналитика и отчёты читают эту таблицу как есть — правок в них не потребуется,
  останется только добавить группировку по `marketplace`, если нужно сравнение площадок.
- **Динамика**: сохранять `products.csv` с датой в имени и считать прирост отзывов —
  это косвенная оценка объёма продаж.
